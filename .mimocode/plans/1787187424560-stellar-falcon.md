## Paso 5: Script de despliegue a Cloud Run

### Crear `deploy-cloudrun.sh`
Script que ejecuta:
1. `gcloud auth configure-docker` (configurar push a Container Registry)
2. `docker build -t gcr.io/PROJECT_ID/observatorio-scraping .`
3. `docker push gcr.io/PROJECT_ID/observatorio-scraping`
4. `gcloud run deploy` con los parámetros correctos

Parámetros clave del servicio Cloud Run:
- `--port 3000`
- `--memory 2Gi` (Chromium necesita RAM)
- `--cpu 2`
- `--timeout 300` (scraping puede tomar varios minutos)
- `--max-instances 3` (controlar costos)
- `--no-cpu-throttling` (necesario para Playwright/Chromium)
- `--set-env-vars` con: `NODE_ENV`, `DEEPSEEK_API_KEY`, `APP_ACCESS_PASSWORD`, `AUTH_SECRET`, `NEXT_PUBLIC_APP_NAME`

| `NEXT_PUBLIC_APP_NAME` | `Observatorio Digital` | No |

## Notas sobre almacenamiento efímero

Con la decisión de "volver a loguear cada vez":
- Los usuarios deberán re-autenticar Instagram/X tras cada cold start
- Para minimizar cold starts, configurar `--min-instances 1` (tiene costo adicional ~$5/mes)
- Los datos del cliente (IndexedDB) NO se ven afectados — viven en el navegador
- El auth de la app (cookies HMAC) es stateless — funciona sin persistencia
